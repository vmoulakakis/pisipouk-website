## Security and external dependencies
Never commit plaintext API tokens, .env files, database passwords, private keys, customer/child records, or credentials to GitHub. Keep secrets in a supported secrets vault or Vercel encrypted environments. For actual full disaster recovery, separately export/snapshot any Supabase/Postgres database, storage bucket, external CMS/files, and third-party state after identifying their providers. Store encrypted backups away from the production account and test recovery in staging. Git-tracked public assets are included at the commit snapshot; externally hosted assets are not automatically included.

## Recovery checklist
1. Verify the selected production commit and build, and inventory tracked assets.
2. Identify database connection from source/project config; backup schema + data using provider-native methods.
3. Export external object storage and verify size/checksums.
4. Inventory every third-party API dependency, and securely record **names, owners and retrieval locations**, not secret values, in this repo.
5. Validate new staging deployment, asset URLs, database consistency and user workflows.
6. Only then claim full one-command disaster recovery.
